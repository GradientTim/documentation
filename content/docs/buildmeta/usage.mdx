## The main BuildMeta

Every project has a `main` BuildMeta. Fields added to it end up in a file called `BuildMeta`. A BuildMeta without
fields generates no file, so projects that never touch `main` get nothing generated:

```kotlin title="build.gradle.kts"
buildMeta {
    main {
        field("appName", "ExampleApp")
        field("appVersion", { project.version.toString() })
    }
}
```

```kotlin tab="Kotlin"
import com.example.generated.buildmeta.BuildMeta

fun main() {
    println("${BuildMeta.appName} v${BuildMeta.appVersion}")
}
```

```java tab="Java"
import com.example.generated.buildmeta.BuildMeta;

public class Main {
    public static void main(String[] args) {
        System.out.println(BuildMeta.appName + " v" + BuildMeta.appVersion);
    }
}
```

Kotlin gets a `public object`, Java a `public final class` with `static final` fields. Strings, chars, numbers and
booleans are generated as compile-time constants.

Every generated file starts with a `// Generated by BuildMeta` header and suppresses linter warnings
(`@file:Suppress("all", "ktlint")` in Kotlin, `@SuppressWarnings("all")` in Java).

## Field values

A field value can be given in three ways. Pick the one that matches where the value comes from:

| Value comes from                              | Use         | Example                                                             |
|-----------------------------------------------|-------------|---------------------------------------------------------------------|
| A constant                                    | plain value | `field("appName", "ExampleApp")`                                    |
| The build itself, but known only later        | lambda      | `field("version", { project.version.toString() })`                  |
| Outside the build (git, files, env vars)      | `Provider`  | `field("commitHash", providers.exec { ... }.standardOutput.asText)` |
| The output of another task                    | `Provider`  | `field("checksum", tasks.named<MyTask>("x").flatMap { it.output }.map { ... })` |

<Callout type="warn">
  Lambdas are evaluated during configuration. With the
  [configuration cache](https://docs.gradle.org/current/userguide/configuration_cache.html) enabled, their result is
  stored once and reused until the build script changes, so a lambda that reads git, the clock or a random value goes
  stale. Starting an external process (like `git`) from a lambda fails the build. Use a `Provider` from Gradle's
  `providers` API instead.
</Callout>

`Provider` values are read when `resolveBuildMeta` runs, not during configuration. A `git` call or a file read through
a `Provider` therefore does not invalidate the configuration cache, and its value is still fresh on every build. When a
`Provider` comes from a task output, that task runs first automatically.

A value must never resolve to `null`, and its type must be [supported](/buildmeta/types).

## Field options

Each field takes an optional block to change its visibility and naming strategy:

```kotlin title="build.gradle.kts"
import dev.gradienttim.buildmeta.meta.FieldMeta

buildMeta {
    main {
        // generated: public const val APP_VERSION: String = "1.0.0"
        field("appVersion", "1.0.0") {
            namingStrategy = FieldMeta.NamingStrategy.SCREAMING_SNAKE_CASE
        }

        field("internalNote", "not part of the public API") {
            visibility = FieldMeta.Visibility.INTERNAL
        }
    }
}
```

| Option           | Values                         | Default                                    |
|------------------|--------------------------------|--------------------------------------------|
| `visibility`     | `PUBLIC`, `INTERNAL`           | `PUBLIC`                                   |
| `namingStrategy` | `KEEP`, `SCREAMING_SNAKE_CASE` | The `fieldNamingStrategy` of the BuildMeta |

<Callout type="idea">
  `INTERNAL` is `internal` in Kotlin. Java has no module visibility, so the field becomes package-private instead.
</Callout>

## Multiple BuildMetas

Use `register` to generate additional files. Each one can set its own file name, package and naming strategy. The
name of a BuildMeta must be a valid identifier (letters, digits and underscores, not starting with a digit), since it
is used in task names and placeholders:

```kotlin title="build.gradle.kts"
buildMeta {
    register("gitMeta") {
        fileName = "GitMeta"
        packageName = "com.example.generated.git"
        fieldNamingStrategy = FieldMeta.NamingStrategy.SCREAMING_SNAKE_CASE

        field("commitHash", git("rev-parse", "--short", "HEAD"))
        field("isDirty", git("status", "--porcelain").map { it.isNotEmpty() })
    }
}

fun git(vararg args: String): Provider<String> =
    providers.exec { commandLine("git", *args) }.standardOutput.asText.map { it.trim() }
```

```kotlin
import com.example.generated.git.GitMeta

println("Commit=${GitMeta.COMMIT_HASH} | IsDirty=${GitMeta.IS_DIRTY}")
```

## Defaults

The extension provides fallbacks that every BuildMeta uses unless it sets its own value:

```kotlin title="build.gradle.kts"
buildMeta {
    fallbackFileName = "BuildMeta"
    fallbackPackageName = "com.example.generated.buildmeta"
    fallbackFieldNamingStrategy = FieldMeta.NamingStrategy.KEEP
    indent = 4
}
```

| Property                      | Description                                      | Default                           |
|-------------------------------|--------------------------------------------------|-----------------------------------|
| `fallbackFileName`            | Name of the generated file and type              | `BuildMeta`                       |
| `fallbackPackageName`         | Package of the generated file                    | `com.example.generated.buildmeta` |
| `fallbackFieldNamingStrategy` | Naming strategy for fields without their own one | `KEEP`                            |
| `indent`                      | Spaces used for indentation                      | `4`                               |

<Callout type="warn">
  Two BuildMetas must not generate the same file. Give each registered BuildMeta a different `fileName` or
  `packageName`. An invalid `fileName`, `packageName` or `indent` is reported by `resolveBuildMeta` together with all
  other problems.
</Callout>

## Tasks

| Task                      | Description                                                                      |
|---------------------------|----------------------------------------------------------------------------------|
| `generateBuildMeta`       | Generates the sources of all BuildMetas.                                         |
| `generate<Name>BuildMeta` | Generates the source of a single BuildMeta, e.g. `generateGitMetaBuildMeta`.     |
| `resolveBuildMeta`        | Resolves all field values and checks them for problems. Runs as part of `check`. |

You rarely need to call them yourself, since compilation already depends on the generated sources.
